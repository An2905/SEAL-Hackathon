Tuân thủ đúng style codebase hiện tại (xem TeamService.java làm tham chiếu): chỉ tạo DTO request trong package com.hackathon.hackathon.dto (ví dụ CreateEventRequest chứa toàn bộ field event + 3 list categories, rounds, criteria dạng inner-class hoặc DTO con đặt cùng package — tùy chọn nhưng không tạo class Response DTO, không tạo Entity, không tạo Repository); toàn bộ logic implement chỉ trong file StaffService.java đã có sẵn (không tạo service mới, không tách helper class) — đặt method trong region //region CREATE EVENT đã được comment sẵn, các hàm phụ check trùng tên/check ngày… cũng nằm cùng file dưới dạng private boolean checkXxx(...) giống pattern checkDuplicateTeamName/checkEventExists trong TeamService; thao tác DB dùng trực tiếp DataSource + Connection + PreparedStatement + ResultSet (không dùng Spring Data, không dùng JPA/Hibernate, không dùng JdbcTemplate), nhớ close() đầy đủ và sử dụng OUTPUT inserted.xxx_id cho SQL Server để lấy ID sau khi insert; method trả về String (success message hoặc lỗi text tiếng Việt) — nếu cần trả nhiều ID cho FE thì build JSON string thủ công giống getMyTeam (StringBuilder + concat), không dùng Jackson/Gson; trong Controller (StaffController — tự tạo nếu chưa có, đặt @RequestMapping("/api/staff") và @CrossOrigin("*") giống AuthController) chỉ làm 1 việc duy nhất là return staffService.createEvent(authHeader, request);, không xử lý logic gì thêm; lấy userId/role từ JWT bằng JwtUtil.extractClaims(authHeader.replace("Bearer ", "")) rồi claims.get("role", String.class) — kiểm tra role phải là COORDINATOR, nếu không trả "Only staff can create events."; không cần viết unit test, không cần Postman collection chia sẻ, dev tự test bằng Postman cá nhân với header Authorization: Bearer <token> lấy từ /api/auth/login của tài khoản staff (staff001@gmail.com đã có sẵn trong DB) và body JSON như mô tả trong paragraph flow ở trên — gửi ít nhất 4 case test: tạo thành công, trùng title, tổng weight ≠ 1.00, và endDate < startDate, screenshot/note lại response để báo cáo khi PR;
