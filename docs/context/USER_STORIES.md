# User Stories: SEAL Hackathon Management System

This document outlines the user stories for the SEAL Hackathon Management System, categorized by functional modules and actors.

## 1. User Management & Authentication

- **US.01:** As a student, I want to register for an account by providing my credentials and university information, so that I can participate in SEAL Hackathon events.
- **US.02:** As an Event Coordinator, I want to review and approve user registrations, so that only authorized participants can join the competition.
- **US.03:** As an Event Coordinator, I want to create temporary Guest Judge accounts, so that industry experts can evaluate specific rounds without having full system access.

## 2. Event & Track Management

- **US.04:** As an Event Coordinator, I want to create a new hackathon event and configure its tracks and rounds, so that I can organize the competition structure for the year.
- **US.05:** As an Event Coordinator, I want to define advancement rules for each round (e.g., Top N teams), so that the system can automatically determine which teams move to the next stage.
- **US.06:** As an Event Coordinator, I want to assign Mentors to specific Tracks, so that they can guide the teams within their domain expertise.
- **US.07:** As an Event Coordinator, I want to manage scoring criteria templates and apply them to specific rounds, so that evaluation remains consistent across different events.

## 3. Team & Submission Management

- **US.08:** As a Team Leader, I want to form a team of 3 to 5 members, so that we can compete together in a Hackathon.
- **US.09:** As a Team Leader, I want to register my team into a specific Track, so that we can compete in the appropriate category.
- **US.10:** As a Team Leader, I want to submit our project URLs and repository links for a specific round, so that our work can be reviewed by judges.

## 4. Assessment & Ranking

- **US.11:** As a Judge, I want to access a dedicated scoring portal to evaluate assigned submissions based on weighted criteria, so that I can provide fair and structured feedback.
- **US.12:** As an Event Coordinator, I want to view real-time rankings and export result reports in CSV/Excel format, so that I can announce the winners accurately and promptly.
- **US.13:** As an Event Coordinator, I want to eliminate a team for rule violations and record the reason in an audit log, so that the competition remains fair and transparent.

## 5. Research Module (RBL)

- **US.14:** As a Judge, I want to participate in a calibration round by scoring sample projects and viewing the score distribution, so that I can align my evaluation standards with other judges.
- **US.15:** As an Event Coordinator, I want to view a dashboard showing score variance among judges, so that I can identify and address inconsistencies in assessment.
- **US.16:** As an Event Coordinator, I want to export anonymized scoring datasets, so that the data can be used for academic research on inter-rater reliability.

## 6. Awards

- **US.17:** As an Event Coordinator, I want to assign and announce prizes based on final rankings, so that winners are recognized for their achievements.
